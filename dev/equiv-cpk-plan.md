# Equiv. Cpk：從「點估計」改為「信賴下界 + 判定」

> 狀態：**設計定案，尚未實作**。本文件僅記錄分析與方案，`src/` 未做任何修改。
> 日期：2026-08-05

---

## 1. 問題

使用者回報 Equiv. Cpk 在高良率時每次模擬跳動很大。追查後確認這是估計器的結構性問題，不是錯覺。

現況（`src/components/TolMaster.tsx:980-985`）Equiv. Cpk 完全由**單側不良個數**決定：

```js
const defectRateToCpk = (failCount, N) => {
  if (N <= 0) return { value: 0, bound: false };
  const p = failCount / N;
  if (p <= 0) return { value: normSInv(1 - 3 / N) / 3, bound: true };
  return { value: normSInv(1 - p) / 3, bound: false };
};
```

良率高時 `failCount` 是個位數整數（服從 Poisson），實測 N=1M 的行為：

| 真值 Cpk | 單側不良數 λ | 每次報出的值（5–95%） |
|---|---|---|
| 1.33 | 33 | 1.31–1.36 |
| 1.50 | 3.4 | **1.45–1.58** |
| 1.67 | 0.27 | 恆為 1.509（天花板） |
| 2.00 | 0.003 | 恆為 1.509 |

兩個症狀：

1. **Cpk ≈ 1.5 抖動 ±0.07** —— 1M 個樣本裡只有約 3 個進入計算，其餘 999,997 個的資訊被完全丟棄。
2. **硬天花板** —— N=1M 時最多只能報 `>1.509`（5M→1.619、10M→1.664）。但 `helpContent.ts:92` 的說明寫「≥1.67 優秀」，工具在預設 1M 下**根本報不出這個等級**。

補充：`Math.random()`（`TolMaster.tsx:626` 等）未設種子，所以同一專案每次按下模擬都會得到不同數字。

## 2. 評估過並否決的方案

### 2.1 GPD 尾端擬合（Peaks-Over-Threshold）—— 實測否決

取最極端 1% 樣本擬合廣義柏拉圖分佈再外推到規格線。理論上把有效樣本數從 3 個拉到 10,000 個。

實測結果（N=1M，8 次重複，PWM 擬合）：

| 情境 | 真值 Cpk | count 法 | GPD top 1% | GPD top 0.1% |
|---|---|---|---|---|
| 純常態 | 1.50 | 1.46–1.58 | 1.51–1.59（偏高 0.05） | 1.46–1.59 |
| 純常態 | 1.67 | 全卡 1.51 | 中位 1.79（偏高 0.12） | 中位 1.75 |
| 純常態 | 2.00 | 全卡 1.51 | **多次回報 ∞** | 中位 2.38 |
| 混合 4N+2U | 1.67 | 全卡 1.51 | 中位 1.84（偏高 0.17） | 中位 1.74 |
| 混合 4N+2U | 2.00 | 全卡 1.51 | **8 次全部回報 ∞** | 中位 2.17 |
| 全均勻 6U | 1.67 | 全卡 1.51 | 1.68 ✓ | 1.66 ✓ |
| 全均勻 6U | 2.00 | 全卡 1.51 | 1.99 ✓ | 2.03 ✓ |

**否決理由：**

1. **對常態尾端系統性高估，且偏向不安全方向。** PWM 擬合常態資料時形狀參數 ξ̂ 幾乎必然為負（常態雖屬 Gumbel domain，但有限樣本收斂極慢）。ξ<0 意味模型認定分佈有**有限上界** `u − β/ξ`；當這個假想上界落在規格線之內，模型直接宣告「不可能不良」→ Cpk = ∞。在最典型的「4 常態 + 2 均勻」堆疊、真值 Cpk 2.0 時，8 次測試全部如此。工程簽核工具給出樂觀的錯誤，比誠實地說「解析不出來」糟得多。
2. **只在真正有界的堆疊才準。** 全均勻那組全對，因為均勻分佈之和確實有硬上界。但本 app 幾乎每個堆疊都含 Normal 項。
3. **門檻選擇沒有客觀解。** 同一組資料 top 1% vs top 0.1% 給出 1.84 vs 1.74（真值 1.67）。教科書靠 mean residual life plot 目視判斷，自動化工具裡沒有人在看那張圖。
4. **對 Empirical 分佈是無效外推。** `sampleEmpirical`（`TolMaster.tsx:654`）從有限筆實測資料 bootstrap，樣本值域被實測資料的凸包鎖死；在那之外做尾端外推等於憑空發明資料裡不存在的極端值。

### 2.2 鞍點近似（Lugannani–Rice）—— 因覆蓋缺口否決

把各項的累積量母函數（CGF）相加，解 `K'(t) = x`，直接算出尾端機率。

實測精度（完全解析，無模擬雜訊）：

| 情境 | 真值 Cpk | 鞍點法 |
|---|---|---|
| 純常態 | 2.00 | **2.0000** |
| 純常態 | 2.50 | **2.5001**（p = 3.19e-14） |
| 混合 4N+2U | 1.67 | **1.6700** |
| 混合 4N+2U | 2.00 | **2.0000** |
| 全均勻 6U | 2.50 | 2.5039 |

效能：10,000 次評估 = 29 ms（單次約 3 微秒）。

CGF 閉式解涵蓋 Normal、Uniform、Fixed、Empirical（bootstrap 分佈的 CGF 精確）、截斷常態、mean drift（常態 ⊗ 均勻，MGF 相乘）。

**否決理由：覆蓋缺口。** 只適用於獨立隨機變數之和：

- `Normal(Sort)` —— 排序配對造成項目間相依，不再是獨立和
- `FitShift` —— 銷孔干涉為非線性，且會產生硬失效（NaN）
- Compression Mode —— 比值不是和（`S/T > c ⟺ S − cT > 0` 有機會轉回線性組合，但需處理分母跨零）

技術上極優秀，但方案帶例外分支，不符合「單一指標、零例外」的要求。

### 2.3 單純加大 N —— 無效

變異 ∝ 1/√λ，要減半抖動需要 4×N。且天花板依然存在：

| N | k=0 時能宣告的最高 Cpk |
|---|---|
| 100k | 1.338 |
| 1M | 1.509 |
| 5M | 1.619 |
| 10M | 1.664 |
| 50M | 1.765 |

## 3. 採用的方案

### 3.1 第一性原理

用抽樣計數估計機率 p，需要約 1/p 個樣本 —— 這是資訊理論極限。任何看似突破它的方法，都是在**注入模型假設**（GPD 注入壞假設，鞍點法注入好假設但有缺口）。既然不接受模型假設，唯一的路是改變**報什麼**，而非**怎麼算**。

關鍵觀察 —— 抖動的分布位置其實是有利的：

| 真值 Cpk | 不良數 | 點估計抖動 | 影響決策嗎 |
|---|---|---|---|
| 1.00 | ~1,350 | ±0.01 | 否，穩定判不合格 |
| 1.33（判定邊界） | 33 | ±0.02 | 否，剛好夠精確 |
| 1.50 | 3.4 | **±0.07** | 否 —— 1.45 和 1.58 都是過 |
| 2.00 | 0.003 | 全卡 1.51 | 否 —— 過就是過 |

**抖動最大的地方，恰好是決策最不敏感的地方。** 這不是巧合：差的設計不良多所以量得準，好的設計不良少所以量不準、但也不需要準。

問題不在統計，在**呈現** —— UI 顯示一個 2 位小數的數字，暗示了它不具備的精度，引誘工程師去解讀雜訊。

### 3.2 指標定義

**「以 95% 信心，Cpk ≥ X」** —— 單側信賴下界，加上對門檻的判定。

給定 N 次模擬中觀測到 k 筆單側不良，求滿足 `P(K ≤ k | λ) = α` 的 λ（Poisson 精確上界，Garwood），再換算：

```
Cpk_lower = normSInv(1 − λ_upper(k, α) / N) / 3
```

### 3.3 驗證：判定穩定性

N=1M，4000 次重複，門檻 Cpk ≥ 1.33：

| 真值 Cpk | 現況點估計 | 95% 下界 | 點估計判「過」 | **下界判「過」** |
|---|---|---|---|---|
| 1.20 | 1.19–1.21 | 1.18–1.20 | 0% | **0%** |
| 1.30 | 1.28–1.32 | 1.26–1.30 | 1.4% | **0%** |
| 1.33（邊界） | 1.31–1.36 | 1.29–1.33 | 54%（擲硬幣） | 3.5%（保守） |
| 1.40 | 1.37–1.44 | 1.34–1.39 | 100% | **99.5%** |
| 1.50 | 1.45–1.58 | **1.40–1.48** | 100% | **100%** |
| 1.67 | 1.51–1.58 | **1.48–1.51** | 100% | **100%** |
| 2.00 | 1.51–1.51 | 1.51–1.51 | 100% | **100%** |

兩件事同時發生：

1. **判定幾乎完全確定** —— 除了真值剛好落在門檻上（那時不確定是**正確的**），判定率不是 0% 就是 100%。
2. **連數字本身也變穩** —— 真值 1.50 時點估計跨度 0.13、下界只有 0.08；真值 1.67 時是 0.07 vs **0.03**。因為 k 小時下界由信心項主導（λ 上界 k=0→3.00、k=1→4.74、k=3→7.75），而點估計被 k 直接拉著跑（1→3→8，8 倍跨度）。

### 3.4 為什麼這是對的指標

- **零例外** —— 純計數 + 精確 Poisson 推論，無分佈假設。Normal / Uniform / Empirical / Normal(Sort) / FitShift / Compression Mode 全走同一條規則，無分岔。
- **誤差方向安全** —— 下界只低估能力，不高估。可用於簽核。GPD 錯在樂觀方向，不可。
- **對 N 單調** —— 加大模擬只會讓下界往上收，永遠不會推翻上一次的結論。
- **不是新模型** —— `TolMaster.tsx:983` 的 `normSInv(1 - 3/N)/3` 就是本下界在 k=0 的特例：`P(K≤0|λ) = e^{-λ} = 0.05 → λ = ln20 = 2.996 ≈ 3`，即 rule of three。這是把已在用、已被信任的邏輯從「只有零不良時」推廣到「所有 k」，**k=0 的行為逐位元不變**。
- **會自己講出極限** —— 天花板意義從「數字壞掉」變成「以此樣本數，最強的誠實宣告是 Cpk ≥ 1.51」，並能反推所需 N：

| 想認證到 | 需要的 N（90% 機率成功） |
|---|---|
| ≥ 1.33 | 100k–300k（預設 1M 綽綽有餘） |
| ≥ 1.50 | 1M–3M |
| ≥ 1.67 | **30M** |

### 3.5 附帶收穫：Solver 解耦

目前 `Equiv. Cpk` 同時被當成「工程判定值」與「Solver 搜尋排序值」使用，這是 `equivReliable` / `nonNormalK` 那套 workaround（`TolMaster.tsx:2572-2596`）存在的根本原因。拆開之後那套 hack 可整段移除：

- **判定** → 信賴下界（保守、通用）
- **排序 / 搜尋** → 參數式 μ/σ Cpk（連續、單調、任何 N 都有值、無天花板；不對外宣稱能力）

## 4. 實作規劃

### 4.1 核心估計器

新增共用模組 `src/lib/capability.ts`（供 `TolMaster.tsx` 與兩個 modal 共用），取代 `TolMaster.tsx:980-985` 的 `defectRateToCpk`：

```ts
// 給定觀測到 k 筆不良 / N 次模擬，回傳 λ 的精確 Poisson 上界（Garwood），
// 即滿足 P(K ≤ k | λ) = alpha 的 λ。k=0, alpha=0.05 → λ=2.996（現有 rule of three）。
const poissonLambdaUpper = (k: number, alpha: number): number => { ... }

// Cpk 的單側信賴下界。取代 defectRateToCpk。
const cpkLowerBound = (failCount: number, N: number, alpha = 0.05):
  { bound: number; point: number; nLimited: boolean } => { ... }
```

要點：

- `poissonLambdaUpper` 對 **k < 20** 用 Poisson CDF 上二分搜尋（迴圈 O(k)，很便宜）；**k ≥ 20** 改用 Wilson–Hilferty 近似 `λ = 0.5 · χ²_{1-α}(2k+2)`，其中 `χ²_p(ν) ≈ ν(1 − 2/(9ν) + z_p√(2/(9ν)))³`。差設計會有 >10⁵ 筆不良，O(k) 迴圈會爆。
- `nLimited = (failCount === 0)`：下界由樣本數而非設計決定。
- **雙側不做 Bonferroni 校正**（每側各用 α=0.05）。理由：保持 k=0 時與現有 rule-of-three 完全一致；實務上較差的一側絕對主導，聯合覆蓋率仍 ≈95%。此簡化須寫進註解。
- 沿用現有 `normSInv`（Acklam），精度到 p~1e-16 綽綽有餘。

## 6. 明確不做

- **不改 Monte Carlo 取樣引擎**（`Math.random` 不換種子）—— 判定已穩定；固定種子會讓「某個種子的運氣」被鎖死，反而掩蓋真實不確定性。若之後仍想要逐位元可重現，再獨立評估。
- 不引入 GPD、鞍點法或任何尾端外推。
- 不動直方圖、Q-Q、SPC modal 等視覺化路徑。
